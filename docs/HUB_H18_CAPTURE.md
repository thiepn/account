# H18 — Reliable Inline Notes Capture

Home gains a staged text capture panel (`PUBLIC_HUB_CAPTURE_PRIVATE=staged-v1`, `PUBLIC_HUB_CAPTURE_CLIENT_ID`, canonical publishable key and Account entry). All values default off. The staged release metadata marks private reads and inline writes, rejecting public-only qualification. Production OAuth enablement and physical-device qualification remain H20.

Users explicitly select their signed-in account’s Notes / Unfiled destination, connect capture, and confirm Save. Capture cannot read/edit existing note bodies. Account adds the independent, default-unchecked `notes.hub.capture.create` purpose; no Inbox read permission is required. Managed OAuth uses the existing exact Home callback with a separate one-use PKCE key. Managed tokens remain in RAM.

The owner RPC derives the account from the authenticated managed JWT and verifies the allowlisted client, current session, active account, native Notes entitlement, connected app, read/write app grants and exact create-consent revision. The private receipts table and authorization helper are inaccessible to native clients. This intentionally guarded authenticated definer RPC triggers the generic Supabase definer advisory; its narrow checks are exercised on the hosted database. RLS with no policies on the private receipt table is intentional.

Drafts are stored as plaintext in this browser, by account ID. The UI explains retention on shared devices and provides Erase. Selecting an account never adopts another account’s draft. Hide/background/sign-out/pagehide clear DOM and tab tokens. Showing or reloading requires explicit destination selection and reconnect. Storage failure stops network submission. A storage event from another tab clears the panel to prevent stale drafts.

A persisted immutable command records uncertainty before sending. Edits to an unsent draft produce a new request ID; submitted commands cannot be changed or erased until reconciled. Timeout/reload/retry uses the same ID, destination and text. Confirmations must match account/request/destination; late and wrong-owner results cannot update the current panel. There is no automatic write retry or optimistic success. New draft is available after confirmation. Stored receipts describe a previous save, not a live read of the note.

The owner serializes commands under the consent lock, locks native app grants, and atomically writes the native text record plus receipt. Sorted JSON checksum serialization matches native Notes sync, including Unicode/quotes/newlines. Receipts contain IDs and a command hash, never text. Replays return the receipt without rewriting edited notes or resurrecting deleted notes. Changed-command reuse rejects. Receipts never expire; 4,096 receipts per owner is a hard capacity limit that fails before creating a note. Captures accept 500 title units/2,000 bytes and 16,000 content units/64,000 bytes. No attachment, checklist or collection API is invented.

Qualification: 234 Hub unit tests; 75 Account unit/UI tests; ten rollback-only hosted capture assertions and all fourteen H17 assertions; native checksum equality; six paired browser cases using actual Hub/Account builds plus mocked network issuance/replies. Browser fixtures complement hosted SQL and are not production OAuth certification. The paired workflow pins the exact Account candidate source.
